## 2. v6 机制变更（相对 v5）

1. **快速波动率反馈**：新增 EWMA 波动率状态（`volatility_ewma_decay`），同时驱动
   （a）订单簿深度压力（波动越高、深度越浅）和（b）Agent 参与度，形成有界的
   volatility–liquidity–impact 闭环；这就是波动聚集、厚尾和量价关系的来源。
2. **随波动率缩放的需求噪声**：噪声与特质信号的订单规模随近期波动缩放
   （`demand_volatility_exponent`），使需求方差具备条件异方差结构。
3. **供给约束的头寸上限**：`max_position_float_multiple` 以每股流通股本为基准
   封顶每名交易者头寸，防止趋势策略在无锚市场中的仓位螺旋。
4. **结算稳健性**：结算引擎执行每日保证金强平（无论提交方向，头寸不得低于杠杆
   下限，且下限按最坏执行价计算）；做市商可通过做空吸收净买入（现金约束不变），
   不再因库存耗尽而冻结成交。
5. 场景定义同步更新：`liquidity_stress` 场景是完整市场深度反馈的更强版本。

## 4. holdout 未过的门槛与已知边界

`full_volatility_clustering_has_decay` 的逐种子判据要求 ACF(20) < ACF(1)。
在约 40% 的种子上，模型存在 |r| 的长记忆平台（ACF(20) ≈ 0.12–0.17），来源是
需求流、深度、活动状态与财富水平等多个慢速状态的叠加低频模式，对单参数调整
不敏感。该平台在调参种子上较弱（开发协议只允许 1 个种子失败，恰好通过），
在未见种子上暴露。**不得**通过降低门槛、更换外生 Student-t/GARCH 基本面或
直接运行正式种子来绕过；需要在新的开发协议版本中解决该长记忆后重新 holdout。
