# 人工金融市场 ABM：三阶段开发计划（渐进式学习版）

> 版本：2026-07-29
> 核心决定：LLM 不进入主线；学习机制按“Logit 模仿 → Bandit/Q-learning → 有条件 PPO”逐步增加。

## 1. 总体架构与原则

Harness 是唯一可以修改市场状态的组件，统一管理：

- 日频时钟、事件队列和信息可见时间；
- 企业公告、消息传播、交易和价格形成；
- 现金、持仓、库存和结算；
- 随机种子、运行配置、状态快照和审计日志。

Company Agent、Trader Agent 和后续主体只能通过 `Policy` 接口提交动作，不能直接修改价格、现金或持仓。

系统使用日频作为主时钟；20日用于投资者策略评估，60日用于企业决策和策略模仿。周频只作为由日频数据派生的调试和稳健性统计。

投资者的金融/环境偏好是稳定属性；学习机制只改变交易策略或企业行动策略，避免把“偏好变化”和“策略学习”混为一谈。

## 2. 第一阶段：确定性基准市场与 Logit 模仿

**预计时间：4–6周**

### 开发顺序

1. 固定核心数据契约：`MarketState`、`AgentState`、`CompanyState`、`Message`、`Edge`、`Order`、`FactorEvent`、`RunManifest`。
2. 制作一个包含公告、订单、价格和结算结果的十日合成场景。
3. 实现单风险资产的日频 Harness、超额需求价格冲击、交易和统一结算。
4. 用数组保存1000个投资者状态，不为每个投资者创建独立的重量级 Python 对象。
5. 实现价值型、趋势型和噪声型交易策略；企业第一阶段只发布外生公告，不进行战略学习。
6. 每60个交易日根据策略适应度进行 Logit 模仿：

   `fitness = 平均净财富增长 - 风险惩罚 - 交易成本`

### 数据顺序

1. 合成数据：测试参数恢复、事件时序和结算守恒。
2. Kenneth French 49 行业日频组合：校准收益率、波动率、自相关和横截面统计。
3. 由日收益复合生成周频统计；不使用周收益替代日频市场时钟。

### 阶段交付与门槛

- 相同配置和随机种子可以精确重放。
- 现金、持仓和市场库存每日守恒。
- 1000个投资者运行250个交易日，无负价格、非法持仓或重复结算。
- 关闭 Logit 学习后，结果精确回到固定规则基准。
- 策略占比变化可以追溯到适应度变化。

未通过确定性、会计守恒或基准统计测试，不进入图和强化学习阶段。

## 3. 第二阶段：图传播、Contextual Bandit 与表格 Q-learning

**预计时间：6–9周**

### 3.1 先验证信息图

1. 用五节点合成静态图验证来源、信任、传播延迟和可见范围。
2. 静态图通过后，再加入互动频率或交易相似度驱动的动态图。
3. 每条消息必须包含来源、生成时间和 `available_at`；Agent 只能读取当前日期已经到达的消息。
4. 13F 只用于验证机构—股票持股关系，不把它当作社交或信任关系。

### 3.2 投资者：Contextual Bandit

投资者每20个交易日选择一次策略，并在下一个窗口内保持该选择。

- 状态：估值偏离、动量方向、波动状态、自身回撤，各离散为三个档位。
- 动作：价值、趋势、逆向、降低仓位。
- 奖励：未来20日净收益，扣除波动惩罚、回撤惩罚和交易成本。
- 同类投资者共享 Bandit 参数，财富、风险厌恶和偏好参数保留异质性。

Bandit 负责“当前环境下选择已有策略”，不负责长周期信用分配。

### 3.3 企业：表格 Q-learning

企业每60个交易日决策一次。

- 状态：融资压力、真实表现—披露差距、核验风险、现金缓冲，各离散为三个档位。
- 动作：真实投入、披露/信号投入、维持现状。
- 奖励分开记录：企业价值变化、融资成本变化、真实投入成本、披露成本和核验处罚。
- 各规模企业共享 Q 表，不为每家公司单独训练模型。

“真实投入/披露投入/维持现状”是通用行动接口；具体含义由后续 Factor Plugin 决定，因此核心不锁死 ESG。

### 阶段交付与门槛

- 五节点图的传播路径、到达时间和消息来源可精确复现。
- 关闭图后，信息集合和订单恢复无图基准。
- Bandit 和 Q-learning 在已知最优解的玩具环境中恢复正确行动。
- 关闭学习后，市场精确回到第一阶段结果。
- 固定更新顺序后，并行执行不会改变结果。
- 全阶段不产生 LLM API Token 费用。

## 4. 第三阶段：真实数据、通用因子与受控扩展

**预计时间：8–14周**

### 数据接入顺序

1. SEC submissions、companyfacts、8-K、10-Q、10-K：企业状态和事件。
2. FRED/ALFRED：宏观变量及历史发布版本。
3. Alpha Vantage：小样本价格原型；具备权限后接 CRSP/WRDS。
4. SEC 13F：机构—股票持股图。
5. EPA 或其他环境数据：仅作为后续可选因子。

所有原始数据写入不可覆盖的快照目录，并记录来源、下载时间、时间范围、版本和哈希。

### 通用 Factor Plugin

所有因素统一转换为 `FactorEvent`，只能通过以下渠道影响市场：

- 改变企业真实基本面；
- 产生公开或局部信息；
- 改变投资者偏好；
- 施加交易或监管约束。

第一个插件使用盈利公告或 8-K 事件，之后再加入宏观、情绪、环境或监管因素。关闭任一插件后，必须恢复上一版本基准。

### PPO 的启用条件

PPO 不属于默认交付。只有同时满足以下条件才启用一个按 Agent 类型共享的 PPO 策略：

- 市场扩展到至少10项资产；
- 研究问题必须处理连续投资权重；
- 离散化后状态—动作表超过100万项，或经过100万次仿真后超过30%的状态仍没有可靠访问记录。

即使启用 PPO，也必须保留固定规则、Bandit 和表格 Q-learning 作为比较基准，不为每个 Agent 训练独立神经网络。

### 阶段交付

- 一个真实 SEC 事件可以按正式可用时间进入仿真，并沿图传播。
- 规则、Bandit、Q-learning、图和因子均可独立关闭。
- 至少500个规则 Agent 完成一年日频仿真。
- 每次运行都能由 Manifest 重建，包含随机种子、配置、数据哈希、运行时间和失败记录。

## 5. 稳定接口与测试

```text
Policy.act(observation) -> Action
Policy.update(Transition)
Transition = state, action, reward_vector, next_state, available_at
LearningConfig = algorithm, update_interval, shared_group, seed
FactorPlugin.events(date, state) -> list[FactorEvent]
```

自动测试覆盖：

- 确定性重放和随机种子隔离；
- 现金、持仓和库存守恒；
- `available_at` 未来信息隔离；
- 图传播路径、延迟和来源追踪；
- 奖励分量计算和学习更新；
- 关闭学习、图或因子后的回归一致性；
- 玩具环境收敛和规模压力测试。

## 6. 明确排除项

- LLM 不进入前三阶段主线；
- 不做每个 Agent 一个 LLM 或一个神经网络；
- 不做实时交易、连续订单簿、强化学习以外的复杂训练框架、网页界面；
- 不把 ESG、某个商业评分或某一种数据源写死进市场核心。
