# 图驱动多智能体人工金融市场：开发阶段计划

## 1. 目标与边界

从空工作区开始，开发一个日频人工金融市场：

- Harness 负责时间、事件、信息可见性、交易执行、结算和完整日志；
- Company Agent、Trader Agent 等通过统一接口读取观察并返回动作；
- 多层有向图负责信息、信任、持股和企业关系；
- Factor Plugin 将财报、宏观、情绪、环境或监管因素转换为统一事件；
- 关闭图、LLM 或因子插件后，系统能够返回对应的上一基准版本。

第一版不做实时交易、连续订单簿、强化学习、网页界面或大规模在线服务。

## 2. 总体开发依赖

两条工作线并行推进，并在真实数据集成阶段汇合。

### 引擎线

数据契约与目录结构
→ 确定性市场内核
→ 规则型企业/交易者
→ 静态图与信息传播
→ 动态图
→ LLM Subagent 策略
→ 因子插件与规模化

### 数据线

合成测试数据
→ Kenneth French 日频行业组合
→ SEC EDGAR 企业与公告
→ FRED/ALFRED 宏观数据
→ SEC 13F 机构持股网络
→ 可选 EPA 环境数据

LLM Subagent 不能先于市场内核、资金守恒和图传播测试接入。

## 3. 技术选型

| 类别 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.12 | 数据、仿真和 LLM 接口生态成熟 |
| 数值计算 | NumPy / SciPy | 市场状态与批量计算 |
| 表格与存储 | DuckDB + Parquet | 本地可复现、易做时间查询 |
| 配置与契约 | dataclass 或 Pydantic | 限制 Agent 输入输出格式 |
| 图 | NetworkX 起步 | 便于验证多层图；规模扩大后再换 igraph |
| 测试 | pytest | 确定性、资金守恒和传播路径测试 |
| LLM 接口 | Provider Adapter | 模型供应商可替换，统一缓存和日志 |

## 5. 每日 Harness 执行顺序

1. 载入当天计划事件和外生数据。
2. Company Agent 在规定日期产生公告或行动。
3. Message 根据图的边权、信任和延迟传播。
4. Trader Agent 读取各自可见的市场状态与消息。
5. Agent 返回结构化买入、卖出或持有动作。
6. Market Clearing Engine 汇总需求并更新价格。
7. Settlement Engine 更新现金、持仓和做市商库存。
8. Harness 更新 Agent 状态、图状态并写入日志。

同一交易日采用同步屏障：所有 Agent 使用相同的日初状态决策，结算完成后才进入下一日，避免并发顺序污染结果。

## 6. 分阶段开发计划

### Stage 0：契约、目录与合成夹具（3-5 天）

做什么：

- 创建 `src/`、`tests/`、`configs/`、`data/` 和 `runs/`；
- 实现上述八个核心数据结构；
- 定义 Harness 的每日状态机；
- 创建两家虚拟企业、五个虚拟交易者和十日合成事件；
- 建立不可覆盖的数据清单格式。

数据：

- 只使用手写的合成 JSON/Parquet；
- 不下载真实市场数据。

完成标准：

- 数据结构可以序列化和反序列化；
- 相同配置生成相同 Manifest；
- 十日合成场景可被完整加载。

### Stage 1：确定性市场内核（1-2 周）

做什么：

- 实现日频时钟和事件队列；
- 实现单资产、买入/卖出/持有订单；
- 使用做市商净需求价格冲击，不做订单簿；
- 实现现金、持仓、库存和成交对账；
- 保存逐日状态与异常诊断。

Agent：

- 暂时使用固定脚本动作，不使用规则推理或 LLM。

数据：

- 使用 Stage 0 合成数据；
- 另建随机收益/基本价值路径做压力测试。

完成标准：

- 250 个交易日重复运行结果完全一致；
- 价格、现金、持仓和库存无非法值；
- 买卖和资金流能够逐日对账；
- 关闭订单后价格保持基准路径。

### Stage 2：规则型企业与交易者（2-3 周）

做什么：

- 实现价值型、趋势型和噪声型 Trader Policy；
- 实现 Company Agent 的公告日程和基础状态；
- Company Agent 先只发布外生公告，不做战略优化；
- 实现 Agent 观察、决策和动作接口；
- 加入 Agent 失败时的安全回退动作 `hold`。

数据：

- 下载并冻结 Kenneth French 49 个日频行业组合，保存 URL、时间、SHA-256 和原始文件；
- 用该数据比较收益、绝对收益、波动聚集和尾部特征；
- 真实数据只用于目标统计和回放，仿真价格仍由市场内核产生。

完成标准：

- 100 个规则型交易者运行 250 日；
- 不同交易者类型产生可区分的订单分布；
- 关闭某类交易者后结果可重复；
- 市场统计流水线能够读取真实数据和仿真数据。

### Stage 3：图与信息传播（2-3 周）

做什么：

- 先实现静态 `MultiDiGraph`；
- 支持 `follows`、`trusts`、`holds` 和 `peer` 边；
- 实现传播延迟、信任衰减、转发和消息来源链；
- 增加无图、随机图、小世界图和无标度图；
- 静态图通过后，再增加按互动或交易相似度更新的动态图。

数据：

- 第一轮完全使用合成图；
- 第二轮下载 SEC 13F 季度文件，构造“机构—证券”二部持股图；
- 13F 只能表示持股关系，不冒充社交关系；
- 社交/信息图在没有可靠公开数据时继续使用可控合成图。

完成标准：

- 在已知五节点图上，消息到达路径、时间和权重完全符合预期；
- 关闭图传播后所有 Agent 只看到公共消息；
- 随机重连保持节点度分布；
- 每条消息能够追溯到源事件。

### Stage 4：LLM Subagent 接入（3-4 周）

做什么：

- 将 Trader Policy 抽象为可替换接口；
- 接入 LLM Trader，但不改变 Harness 和结算代码；
- 输入只包含结构化观察，不提供未来数据；
- 输出限定为 JSON：`action/asset_id/quantity/confidence/reason_code`；
- 缓存每次请求与响应，支持离线重放；
- Company Agent 先使用受限决策集合，不生成任意数值。

运行方式：

- 先用 10-20 个 LLM Agent 跑 20-60 日；
- 每日只激活部分 Agent；
- 无效输出自动重试一次，仍失败则执行 `hold`；
- 数值状态以 Harness 为准，LLM 无权直接修改现金和价格。

完成标准：

- 所有 Agent 输出通过 Schema 校验；
- 使用缓存后可以完全重放同一实验；
- 替换回规则 Policy 时市场内核不需要修改；
- 记录模型名、版本、Prompt 哈希、温度和调用成本。

### Stage 5：真实企业、宏观数据与 Factor Plugin（3-5 周）

做什么：

- 实现通用 `FactorEvent` 插件；
- 因子只能通过基本面、信息、偏好或约束渠道进入；
- 实现关闭插件后返回无因子基准的测试；
- 将企业公告转为结构化 Message；
- 支持交易者日频行动、企业季度行动的多时间尺度。

数据：

- SEC `submissions`：公司申报历史和接受时间；
- SEC `companyfacts`：XBRL 财务事实；
- 8-K、10-Q、10-K：企业事件与公告内容；
- FRED/ALFRED：利率、通胀和宏观数据及历史版本；
- 小样本个股日频价格可使用 Alpha Vantage 做原型；
- 长历史、退市和正式个股总体需要后续申请 WRDS/CRSP。

第一个插件：

- 使用 8-K 或财务披露事件；
- `available_at` 采用 SEC 接受时间；
- 不需要分析师预期时，将事件定义为“披露发生/财务指标变化”，不伪造盈利意外。

完成标准：

- 一个 SEC 公告可按真实可用时间进入仿真；
- 消息沿图产生不同的 Agent 可见集合；
- 插件关闭后精确复现 Stage 4 基准；
- 原始数据均有下载记录、哈希和许可说明。

### Stage 6：扩展、校准和规模化（4-8 周）

做什么：

- 从单资产扩展到少量企业/资产；
- 引入企业战略决策和资本市场反馈；
- 增加媒体、分析师或监管 Agent，但一次只加一种；
- 使用批量推理、角色共享或激活采样降低 LLM 调用；
- 对无图、随机重连图、规则 Agent 和 LLM Agent 做成组实验。

数据：

- SEC 13F 构造持股网络；
- SEC/FRED 提供点时事件；
- 获得权限后接入 CRSP 个股价格与退市数据；
- 环境应用需要时再接入 EPA GHGRP/TRI/ECHO。

完成标准：

- 50-100 个 LLM Agent 或 500 个规则 Agent 完成一年日频仿真；
- 每次运行都可由 Manifest 重建；
- 图、因子和 Agent 策略均可独立关闭；
- 输出计算时间、调用次数、内存和失败率。

## 7. 数据目录与冻结规则

建议目录：

```text
data/
├── raw/<source>/<retrieved_at>/
├── interim/
├── processed/
└── manifests/
```

每次下载必须记录：

- 来源 URL 和请求参数；
- UTC 下载时间；
- 数据实际发布日期或 SEC 接受时间；
- 文件 SHA-256；
- 行数、列数和覆盖日期；
- 许可或使用限制。

原始文件只追加新版本，不覆盖旧快照。

## 9. 关键设计决策

| 决策 | 当前选择 | 原因 |
|---|---|---|
| 主频率 | 日频 | 支持价格、公告和传播；企业使用季度子时钟 |
| 第一版市场 | 做市商净需求价格冲击 | 比订单簿简单，先验证系统闭环 |
| 图顺序 | 合成静态图 → 合成动态图 → 实证持股图 | 先保证机制可测，再引入脏数据 |
| Agent 顺序 | 固定动作 → 规则 Policy → LLM Policy | 能隔离市场、网络和模型错误 |
| 并发方式 | 每日同步屏障，Agent 可并行决策 | 避免调用完成顺序改变市场结果 |
| 数据策略 | 原始快照不可覆盖 | 支持点时实验和结果复现 |
